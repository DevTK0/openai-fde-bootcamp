# Autonomous run

Adapted from [upstream pstack](https://github.com/cursor/plugins/blob/df581122cde17e6e27686b5a448bde23e4ad4318/pstack/skills/poteto-mode/playbooks/autonomous-run.md). The MIT notice is in [LICENSE](../../LICENSE).

You own the exit condition. Define done, then drive to it within the user's scope and the active Codex session. Use this playbook when asked to work autonomously until a stated outcome. An explicit autopilot queue uses its own playbook. For a workflow that still needs design, use the **figure-it-out** skill first.

1. State the exit condition as a checkable predicate before the first iteration, such as tests green, a reproduced defect fixed, or an authorized set of PRs merged. Resolve repository-owned skills through the [pstack entrypoint](../SKILL.md) and read each referenced skill before applying it.
2. Pick a wait mechanism from the available Codex tools. For an event such as CI completion, a merge, or a ref advancing, inspect that event directly and use bounded waits between checks. Otherwise choose an interval based on when a new result is likely. Keep individual blocking waits within 60 seconds so the session can respond to user input. Ordinary runs stay sequential. Watcher subagents require an explicitly invoked swarm or an executing autopilot workflow under the entrypoint's isolation and capacity rules. Do not assume Cursor's `/loop` command or an unattended scheduler exists.
3. Each iteration makes the smallest change the evidence justifies, verifies it against the predicate, and commits if it advanced. Undo only task-owned changes that did not help, preserving unrelated and pre-existing work. Apply **principle-sequence-verifiable-units**, verifying each unit before the next instead of batching checks at the end.
4. Address mid-run discoveries that block the predicate and fall within the authorized scope through **pstack**. These may include broken skills, related bugs, flaky verifiers, review noise, or tooling failures. Put separable fixes in their own PR when appropriate. Record unrelated findings without expanding the assignment. Proceed with authorized reversible fixes. Surface irreversible actions that lack authorization, genuine product or preference calls no experiment can settle, or a real dead end. Return to the predicate after each side fix. Use Opening a PR for publication and Shipping for authorized landing, including its independent verification gate. This playbook does not grant merge or deployment authority.
5. Checkpoint every iteration via **show-me-your-work**, with a row for what changed and whether the predicate moved.
6. Stop when the predicate is met. A plateau calls for a different evidence-backed approach, not a weaker predicate. Surface a genuine dead end rather than repeating failed attempts. Honor user stop requests and session limits. Before the session ends, stop any workers you started and persist the predicate state, exact revisions, PRs, evidence, blockers, and next action in a handoff. An interrupted run is incomplete; do not claim it continues after the session.

Reply with the exit condition, iterations run, what landed, what was discarded, and the final predicate state. Include the decision-trail path and any handoff or blocker.
