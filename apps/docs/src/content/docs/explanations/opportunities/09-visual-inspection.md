---
title: Making before-and-after condenser inspections comparable
description: Why standardized photographs and reviewed area measurements may be more useful than inconsistent descriptions of visible obstruction.
---

One inspector describes a condenser as partly blocked before cleaning. Another later records that it looks clear. Those descriptions may both be reasonable, yet an engineer trying to compare visits cannot tell whether the condition changed enough to matter or whether the inspectors used different standards. The proposed project would produce a repeatable measurement of one visible condition from a standardized photograph, with an annotation that an inspector can accept or correct. The initial purpose is to make the inspection record more consistent, not to decide whether the vehicle is mechanically sound.

The fictional LionLink component observations include a cooling condenser with before-and-after obstruction percentages and a written condition. The [evidence sources](/docs/applications/) identify these as selected maintenance observations rather than a complete fleet survey. The dataset contains no corresponding photographs, labelled image regions, or measurement protocol. Its percentages therefore show the kind of observation the exercise wants to record. They do not demonstrate that people can reproduce the measurement or that a computer can infer it accurately. Establishing that measurement is the first investment decision.

The proposed quantity needs a precise definition. For a first prototype, it might be the proportion of an agreed visible condenser region that an inspector identifies as obstructed. That is an image-area measure. It is not automatically the percentage loss of airflow, cooling performance, or remaining component life. A visually clear surface can still conceal a fault, and some visible material may affect function more than its area suggests. Engineering must decide whether a consistent area record is useful for comparing cleaning outcomes. If the intended business decision actually requires airflow measurement, photographs alone would be the wrong project.

A standardized capture process may deliver much of the value without a trained model. The team could specify the component view, camera distance, lighting expectations, and a reference that helps confirm scale and orientation. Inspectors could then mark obstruction manually on the image. This would preserve visible evidence and make disagreements reviewable. Automation becomes worthwhile only if annotation takes enough time, or varies enough between inspectors, that software assistance improves the process. Beginning with capture and manual agreement avoids spending on image recognition before the target measurement is stable.

The automated mechanism is image segmentation, which assigns parts of an image to defined regions. The system first identifies the condenser inspection area, then marks the portion that appears obstructed. It divides the marked area by the total inspection area to produce the proposed percentage. For a purely illustrative example, if an accepted image has one hundred comparable area units and twenty are marked obstructed, the result is twenty percent. If the camera view omits part of the condenser, that calculation is not a comparable whole-component measure. The system must reject or qualify the capture rather than disguise the missing area with a precise number.

The inspector would see the original image and the proposed outlines together. A correction should change the measured area transparently and remain attached to the inspection record. Before-and-after comparisons require the same defined region and a sufficiently similar view. Otherwise, a different angle or shadow could appear to show successful cleaning. The system should retain both captures and their quality checks so a reviewer can distinguish an actual condition change from a capture change. The user-facing result is a reviewed observation, with the person responsible named, rather than an automatically approved maintenance outcome.

The first deliverable should be a controlled capture study on a bounded set of physical components. Two qualified inspectors should independently mark the same images using one written definition. Repeat captures of unchanged components should test how much the camera process alone changes the result. Only if that variation is acceptably small should the team compare a simple image-processing method with a trained segmentation model. Images of the same component should stay together when separating development and evaluation data. Otherwise, familiar markings or backgrounds could make the method appear to generalize when it is recognizing the component already seen.

The project needs workshop access, a capture device, an approved image protocol, annotation time, and an Engineering owner for the definition. Staff also need a practical place to store images against the correct inspection and component. Captures should avoid people and unrelated identifying material where possible, and access should follow the workshop's existing record controls. The initial integration can attach a reviewed annotation to a maintenance record. It should not open repair orders or change vehicle release status. Those decisions need evidence and authority beyond the visible obstruction measurement.

Failure behavior is central because difficult photographs are inevitable. Reflections, poor lighting, dirt on the camera, occlusion, or an unfamiliar component view should cause a request for a new image or a manual inspection. The interface must make an unmeasurable capture visibly different from a clean condenser. If the model is unavailable, inspectors should retain the photograph and use the approved manual annotation process. Corrections can inform future model development after review, but every correction should not automatically retrain a live model. Engineering needs control over changes to the measurement method so results remain comparable over time.

A successful pilot would show repeatable measurements on unchanged components, meaningful agreement with independent inspector annotations, and a manageable rate of rejected images. It should measure the time to capture, review, and correct an image as well as model error. If the software saves drawing time but forces repeated photographs in a cramped workshop, it may add work overall. The team should also ask whether the resulting record changes a useful decision, such as confirming completion of a defined cleaning task or identifying a case that deserves further inspection. Agreement with a label alone does not establish operating value.

LionLink should begin with the capture and annotation study, not a fleet-wide vision model. If inspectors cannot agree on the region or on what counts as obstruction, the measurement definition needs repair first. If standardized photographs and manual marking already meet the need, that simpler implementation may be sufficient. A model deserves funding when it reduces the effort of a measurement that Engineering already considers reliable and useful. Claims about better cooling, fewer failures, or longer component life would require a separate study connecting the observed condition to those outcomes.
